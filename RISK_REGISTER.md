### Registry residual limits

These limits belong to «M5 registry mutation». They are properties of the current code.

1. A write, a removal, or a restore that does not finish can leave a partial set of keys. `RestoreImageBackups` says so when the restore fails or does not match the snapshot: the operation is not atomic and the registry may be partial.
2. Rollback is best-effort. It is not guaranteed. HKCU is not updated inside a transaction. `RestoreBackup` skips a created key when subkeys remain, and it skips a key whose owner is present and is not the backup owner.
3. A foreign subkey can block complete removal of a node. Removal and `CurrentUserRegistryStore.DeleteKey` both refuse a key that still has subkeys. The owned parent is then left in place. This register does not propose deleting foreign keys by hand.
4. Exit code 0 from `ApplyImages`, `ApplyContent`, or `ApplyMedia` means the requested procedure returned without a registry exception. By itself it is not proof that every planned key is absent.
5. Registry operations need an independent check afterwards. The in-memory suites do not replace a read of the real hive.

The older `ShellIntegration` path is not this model. It has no `FlipOwner`. When the stored command matches, removal uses `DeleteSubKeyTree`. When the command differs, the key is preserved. That path is still reachable and is legacy.

### Post-removal observation in M5.4.6

[TEST_RESULTS.md](TEST_RESULTS.md) records this observation. DOC-01.5-C did not reproduce it and did not read a laboratory log from the repository, because no such log is stored there.

The first PowerShell check after removal reported `MENU_RESIDUI` 15/15. Later independent checks through the .NET registry API reported 0/15. Explorer showed the WAV and MP4 menus absent. The final audit is PASS. The cause of the first discrepancy was not determined.

This register does not classify that first reading as a demonstrated defect of the program. It also does not assert that all 15 keys were still present after removal. The audit follows the later checks and the Explorer check, not the first PowerShell reading alone. The observation stands as a traceability and measurement limit on post-removal verification, and as an item to monitor with the residual limits above. One probe, including exit code 0, is not sufficient by itself.
